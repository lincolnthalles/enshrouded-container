## Purpose

Full server lifecycle orchestration from startup through shutdown.

## Requirements

### Requirement: Server lifecycle orchestration

The `start` command SHALL orchestrate the full server lifecycle by delegating to extracted modules: `settings` for configuration, `resources` for monitoring, `utils` for shared helpers, and `download` for DepotDownloader operations. The `run()` function in `commands/start.py` SHALL remain the single entry point. Resource monitoring functions SHALL be imported from `enshctl.resources` instead of being defined locally.

#### Scenario: Resource monitoring delegated

- **WHEN** the server starts with `RESOURCE_POLL_INTERVAL=60`
- **THEN** the resource poller SHALL be started via `enshctl.resources.start_resource_poller()`

#### Scenario: Backup spawning unified

- **WHEN** a scheduled backup or a cold/emergency backup is triggered
- **THEN** the same `_run_backup(extra_args=None|list[str], detach=False)` function SHALL be used for all paths, with cold and emergency backups passing `detach=True` so the child survives the parent's process group (`start_new_session=True`)

### Requirement: Startup sequence

The entrypoint SHALL execute the following startup sequence in order: (1) resolve and download game version, (2) build the game symlink tree, (3) generate Wine DLL overrides from mod files, (4) generate enshrouded_server.json and write to config dir, (5) start enshrouded_server.exe via Wine at `/data/gameserver/enshrouded_server.exe` with the computed `WINEDLLOVERRIDES` in its environment.

#### Scenario: Full startup sequence

- **WHEN** the container starts
- **THEN** the following SHALL happen in order:
  1. Game version is resolved and downloaded if needed to `/data/manifests/`
  2. Symlink tree is built at `/data/gameserver/` from manifests and mods
  3. Wine DLL overrides are generated by scanning `/data/mods` for `.dll` files
  4. `enshrouded_server.json` is generated and written to `/data/config/`
  5. Steam AppID `2278520` is set in environment
  6. `xvfb-run wine /data/gameserver/enshrouded_server.exe` is spawned as a child process

#### Scenario: Startup fails fast

- **WHEN** any startup step fails (e.g., network error during download)
- **THEN** the container SHALL exit with a non-zero code and log the error

### Requirement: Graceful shutdown

The `start` command SHALL handle `SIGTERM` by stopping the backup scheduler, sending `SIGINT` to the server process, waiting up to `SHUTDOWN_TIMEOUT` (default 60s) for it to exit, waiting up to `SHUTDOWN_BACKUP_WAIT` (default 120s) for any in-progress backup to release the lock, creating a detached cold backup if configured, and cleaning up Wine last. The handler SHALL ignore repeat signals once shutdown is in progress. The `_make_sigterm_handler` function SHALL remain in `commands/start.py` as it is tightly coupled to the server lifecycle.

#### Scenario: SIGTERM triggers cold backup

- **WHEN** `SIGTERM` is received and `BACKUP_COLD=1` and saves exist
- **THEN** a detached cold backup subprocess SHALL be spawned via `_run_backup(["--cold", "--wait", "<SHUTDOWN_BACKUP_WAIT>"], detach=True)`

#### Scenario: Shutdown order is SIGINT, backup, Wine cleanup

- **WHEN** the container receives SIGTERM with a running server and `BACKUP_COLD=1`
- **THEN** SIGINT SHALL be sent first, the cold backup SHALL complete second, and Wine server cleanup SHALL run last

#### Scenario: Graceful shutdown without cold backup

- **WHEN** the container receives SIGTERM and `BACKUP_COLD=0`
- **THEN** the game server SHALL receive SIGINT and have up to `SHUTDOWN_TIMEOUT` seconds to shut down, with no backup created

#### Scenario: Force kill after timeout

- **WHEN** the game server does not exit within `SHUTDOWN_TIMEOUT` seconds after SIGINT
- **THEN** the entrypoint SHALL send SIGKILL to the process, then proceed to the backup and Wine cleanup steps

#### Scenario: Cold backup waits for in-progress backup

- **WHEN** the container receives SIGTERM and a scheduled backup subprocess holds the lock
- **THEN** the cold backup SHALL wait up to `SHUTDOWN_BACKUP_WAIT` seconds for the lock instead of skipping, and SHALL skip with a warning only if the wait expires

#### Scenario: Repeat signal ignored

- **WHEN** a second SIGTERM or SIGINT arrives while shutdown is already in progress
- **THEN** the handler SHALL return immediately without restarting the sequence

### Requirement: Emergency backup on unexpected exit

When the game server exits unexpectedly (not SIGTERM-initiated) and `BACKUP_EMERGENCY=1`, the entrypoint SHALL spawn an emergency backup subprocess before exiting.

#### Scenario: Emergency backup spawned

- **WHEN** the game server exits with a non-zero code and `context.shutdown_requested` is false and `BACKUP_EMERGENCY=1`
- **THEN** `_run_backup(["--emergency"])` SHALL be executed before `sys.exit()`

#### Scenario: Emergency backup skipped when disabled

- **WHEN** the game server exits unexpectedly and `BACKUP_EMERGENCY=0`
- **THEN** no backup subprocess SHALL be spawned

#### Scenario: Emergency backup skipped when no saves

- **WHEN** the game server exits unexpectedly and `/data/saves` is empty or missing
- **THEN** no backup subprocess SHALL be spawned regardless of `BACKUP_EMERGENCY`
